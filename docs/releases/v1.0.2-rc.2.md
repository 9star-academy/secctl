# v1.0.2-rc.2 — Ubuntu SSH socket 端口兼容验收版

修复 Ubuntu 26.04 由 `ssh.socket` 持有监听时，修改 SSH 端口无法生效的问题。继续作为预发布版供空白测试服务器验收。

## 本次修复

- 检测实际 SSH 启动模式；普通服务仍使用重载，socket 模式调用已有系统生成器并切换监听，不关闭 socket 激活、不添加永久覆盖文件。
- 切换前要求 `KillMode=process`，保留已登录会话；先核对生成的目标监听，再切换服务并核对真实端口。
- 将原 socket 监听写入独立回滚状态；超时、中断、挂断或应用失败时恢复 SSH 配置和监听。恢复失败保留状态供 systemd 重试。
- 增加真实 SSH 登录、确认、原会话保留、超时、SIGINT 与 SIGHUP 回滚的 Ubuntu 26.04 socket / Ubuntu 22.04 service CI，以及 Ubuntu 26.04 UFW/Docker 生命周期验收。

## 安装或升级

```bash
curl -fsSL https://raw.githubusercontent.com/9star-academy/secctl/v1.0.2-rc.2/scripts/install.sh | sudo env SECCTL_VERSION=v1.0.2-rc.2 bash
secctl --version
```

预期 `secctl version v1.0.2-rc.2`。本版为预发布，必须明确指定版本。先完成旧版本待确认的 SSH 操作，再升级。

## 验收

[Ubuntu 26.04 完整命令与预期结果](https://github.com/9star-academy/secctl/blob/v1.0.2-rc.2/docs/acceptance-ubuntu-26.04.md) 包含 UFW、Docker、SSH 22/22022 切换、确认、回滚、整机重启及恢复步骤。

保留旧 SSH 会话及云控制台入口；在云安全组允许目标端口，用新终端实际登录后才在原终端输入 `confirm`。临时 systemd 回滚定时器不能保证跨整机重启恢复，必须先确认再重启。

自定义 SSH Match/复杂 Include、自定义固定 socket 监听及不安全的 KillMode 会明确拒绝自动修改。Docker Shield 仍限 UFW + Docker iptables 的默认 IPv4 bridge；自动封禁、独立白名单管理、IPv6 容器及原生 nftables 尚未支持。用户自己的云安全组、外网连接及整机重启仍需按文档验收。
